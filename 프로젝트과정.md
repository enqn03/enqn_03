# AMMT Layer-Camera 기반 실시간 이상 후보 위치 탐지

## 1. 프로젝트 목적

이 프로젝트는 LPBF(Laser Powder Bed Fusion) 적층제조 공정의 layer-camera 시계열에서 **실시간 노이즈 저감**과 **이상 후보 위치 탐지**를 수행하는 모델을 구축한다. 목표 출력은 제조 layer와 카메라 좌표를 포함하는 `(x_pixel, y_pixel, layer_z, score)`이며, 초기 단계의 score는 **확정 결함 확률이 아닌 이상 후보 점수**로 해석한다.

프로젝트는 의료 CT가 아닌 제조 현장 공정 계측 데이터를 다룬다. layer-camera 신호와 사후 XCT 등록 자료를 연결해, 공정 중 조기 경보와 사후 품질 검증을 단계적으로 결합하는 것을 장기 목표로 한다.

| 항목 | 정의 |
|---|---|
| 핵심 과제 | 공정 영상 denoising, 이상 후보 heatmap, 후보 좌표 추출 |
| 즉시 목표 | A 단계에서 가능한 조기 이상 후보 탐지와 위치 출력 |
| 확장 목표 | B 단계 재평가 및 A/B fusion heatmap |
| 최종 검증 축 | 사람 검토 mask 또는 등록 XCT 기반 weak supervision |
| 현재 제외 범위 | YOLO class, bounding box, 확정 결함 판정, 자동 품질 합격/불합격 판정 |

> **해석 원칙:** A/B 차이 또는 모델 score만으로 결함을 확정하지 않는다. 모든 출력은 사후 검증 전까지 이상 후보로 표시한다.

## 2. 데이터 체계와 신호 의미

주 데이터는 NIST AMMT Overhang Part X4의 layer-camera, 공정 신호, metadata 및 등록 XCT 자료다. 원본은 `raw_original/`에 보존하며, 영상 분석은 `tifffile.memmap(..., mode="r")` 기반의 읽기 전용 접근을 사용한다.[1]

| 데이터 | 구조·역할 | 프로젝트 내 해석 |
|---|---|---|
| `LayerCameraAfterSpreading.tif` (A) | `TZYX=[3,250,2000,2000]`, `uint16` | 분말 도포 직후·레이저 전 영상. 조기 경보 입력 |
| `LayerCameraBurned.tif` (B) | A와 동일 구조 | 레이저 스캔 후 영상. 사후 재평가·fusion 입력 |
| DAQ·XYPT | layer/scan 조건을 설명하는 공정 시계열 | 이후 보조 feature 후보 |
| Build·Layer Camera metadata | 장비·좌표·calibration 정보 | camera pixel에서 machine 좌표로의 변환 근거 |
| 등록 XCT 자료 | 사후 품질의 공간 참조 | weak target·위치 검증 후보 |

A와 B는 같은 `(layer_z, LED)`로 대응시킬 수 있지만 서로 denoising의 clean target이 아니다. B−A에는 레이저 용융, 반사, 설비 구조 등 정상 공정 변화가 포함되므로, raw 차이를 직접 defect label로 사용하지 않는다.

## 3. 데이터 검증에서 확인된 사실

### 3.1 Hyperstack 구조와 A/B 대응성

A와 B는 모두 ImageJ logical hyperstack이며, 물리 TIFF page 수가 아닌 logical 축 `TZYX`로 접근해야 한다. 따라서 page index 방식이 아니라 memmap 인덱싱을 사용한다.

| 검증 항목 | 확인 결과 | 기술적 결정 |
|---|---|---|
| 축·shape·dtype | A/B 모두 `TZYX=[3,250,2000,2000]`, `uint16` | `(z, LED)` 대응 sequence 구성 가능 |
| 시간 의미 | T=LED 3개, Z=제조 layer 250개 | 모델 시간축은 Z, LED는 입력 channel |
| A/B 정합 표본 | 표본 상관계수 약 0.75–0.87 | 대규모 좌표 불일치는 낮지만, A/B 차이를 label로 사용하지 않음 |
| 원본 접근 | 읽기 전용 memmap | 원본 TIFF 재저장·bulk 변환 금지 |

### 3.2 포화와 ROI 문제

초기 ROI `(250,250)–(1750,1750)`와 중첩·수직 이동 후보를 비교했다. 중심부를 더 작게 crop해도 포화가 완화되지 않았으며, 모든 후보에는 상당한 full-scale saturation이 남았다.

| ROI 후보 | 평균 full-scale saturation | 최악 표본 saturation | 요약 |
|---|---:|---:|---|
| `wide (250,250)–(1750,1750)` | 34.53% | 92.42% | 평균 포화가 가장 낮은 비교 후보 |
| `lower (350,450)–(1650,1750)` | 35.56% | 91.28% | 최악 표본 기준은 가장 낮음 |
| `inner (350,350)–(1650,1650)` | 38.78% | 96.42% | 중심 crop으로 개선되지 않음 |
| `upper (350,250)–(1650,1550)` | 40.21% | 97.19% | 포화 영향이 큼 |
| `inner (450,450)–(1550,1550)` | 40.52% | 99.10% | 포화 영향이 가장 큼 |

wide 후보에서 A LED1/LED2의 평균 포화율은 35.62%·51.19%, B LED1/LED2는 45.44%·49.94%였다. LED3는 A 11.90%, B 13.11%로 상대적으로 낮았다. 따라서 ROI crop만으로 포화를 해결하지 않으며, **stage·LED별 saturation validity mask와 stage·LED별 normalization**을 모델 입력 정책에 포함해야 한다.

> **현재 ROI 상태:** wide 후보는 공정 영역을 유지하는 작업 후보지만, 최종 model ROI는 아직 확정되지 않았다.

## 4. 각 검증 단계가 필요한 이유

산업 공정 영상에서는 관측 강도 변화가 곧 품질 이상을 뜻하지 않는다. 아래 검증은 모델이 장비 구조, sensor ceiling, 미래 정보 또는 정상 공정 변화를 이상으로 학습하는 것을 막기 위해 수행했다.

| 검증 단계 | 검증하지 않을 때의 위험 | 확인한 사실 | 이후 모델·데이터 결정 |
|---|---|---|---|
| Hyperstack 구조 audit | 물리 TIFF page를 논리 layer로 오인해 잘못된 frame을 학습할 위험 | A/B 모두 `TZYX=[3,250,2000,2000]`, T=LED·Z=제조 layer | memmap 기반 `(z, LED)` 인덱싱을 사용하고, Z를 sequence 시간축으로 정의 |
| A/B pair 대응 audit | 서로 다른 좌표의 A/B를 비교하거나 B−A를 결함 label로 오인할 위험 | A/B는 대응 가능하지만 차이에는 정상 용융·반사 변화가 포함 | B−A는 fusion feature 후보일 뿐 direct defect label로 사용하지 않음 |
| ROI 후보 비교 | 시각적으로 보이는 crop만 선택해 공정 영역을 잃거나 포화를 해결했다고 잘못 판단할 위험 | 중심 crop도 포화를 낮추지 못했고 wide 후보가 평균 포화가 가장 낮음 | wide ROI를 working ROI로 사용하되 final ROI는 보류 |
| Saturation audit | `65535` sensor ceiling을 밝은 정상 신호 또는 이상 신호로 학습할 위험 | LED1·2, 특히 B 단계에 38–51% full-scale saturation | per-LED validity mask를 입력·loss에 사용하고 mask 이미지 저장은 하지 않음 |
| Causal split manifest | 미래 layer 또는 validation/test layer 정보를 학습에 누수할 위험 | K=4, 두 3-layer guard band, 154/39/48 endpoint 분할 | history는 과거 layer만 사용하고 normalization은 train history z=1–157만 사용 |
| Train-only normalization | validation/test 밝기 분포를 학습 단계에 미리 반영해 평가가 낙관적으로 보일 위험 | stage·LED별 p01/p99와 saturation 분포가 크게 다름 | stage·LED별 독립 normalization config를 고정하고 validation/test에서 재추정하지 않음 |
| Registered XCT sparse-target audit | sparse machine-coordinate XCT 값을 dense camera defect heatmap 또는 binary defect label로 오인할 위험 | CSV row는 XYPT 위치의 결합 측정점이며 XCT voxel value·공간 support·층별 finite coverage가 따로 존재 | 먼저 sparse continuous weak target·support mask를 검증하고 machine XY→camera pixel calibration 후에만 heatmap 생성 |

> **검증의 목적은 데이터를 더 깨끗하게 보이게 만드는 것이 아니라, 모델이 실제 공정 이상과 관측 시스템의 구조적 artifact를 구분할 수 있는 입력 규칙을 만드는 것이다.**

## 5. 인과적 시계열 분할

실시간 시나리오에서는 endpoint layer `z`를 예측할 때 미래 layer를 사용하면 안 된다. 현재 sequence 길이는 `K=4`이며, 한 sample의 history는 `[z-3, z-2, z-1, z]`다. 두 개의 3-layer guard band를 두어 validation/test endpoint가 다른 split의 endpoint를 history로 사용하지 않도록 했다.

| 구분 | endpoint z 범위 | endpoint 수 | history 예시 | 용도 |
|---|---:|---:|---|---|
| Train | `4–157` | 154 | z=4 → `1;2;3;4` | 학습·normalization 통계 추정 |
| Guard 1 | `158–160` | 0 | validation의 직전 context | 분할 경계 buffer |
| Validation | `161–199` | 39 | z=161 → `158;159;160;161` | 모델 선택·hyperparameter 평가 |
| Guard 2 | `200–202` | 0 | test의 직전 context | 분할 경계 buffer |
| Test | `203–250` | 48 | z=203 → `200;201;202;203` | 최종 일반화 평가 |

전체 241개 endpoint sample은 train/validation/test에 각각 154/39/48개로 배분된다. 이는 목표 비율 64%/16%/20%에 대한 정수 근사치인 63.90%/16.18%/19.92%다.

생성된 `manifests/causal_sequence_manifest.csv`는 image pixel을 저장하지 않고 sample index와 history layer만 기록한다. `manifests/split_policy.json`은 split 경계, guard, causal rule을 명시하는 재현성 문서다.

## 6. 현재 모델 설계

모델은 A/B 각각을 완전히 분리한 두 시스템보다, 공통 시각 특징을 공유하는 backbone과 stage별 head를 사용한다. 이는 LED·광학적 구조·적층 문맥의 공통 특징을 공유하면서, 레이저 전후의 신호 의미 차이는 head와 conditioning에서 분리하기 위함이다.

| 구성 요소 | 입력 | 출력 | 역할 |
|---|---|---|---|
| Shared causal backbone | 최근 K개 layer의 3 normalized LED + 3 validity-mask channel | 시간 문맥 feature | 과거 layer만 사용하는 공통 denoising·spatial feature |
| A head | A stage feature | A heatmap | 레이저 전 이상 후보 조기 탐지 |
| B head | B stage feature | B heatmap | 레이저 후 이상 후보 재평가 |
| Fusion head | A/B feature, 선택적 공정 feature | fusion heatmap | B 확보 후 A/B 정보를 결합한 위치 재평가 |
| Coordinate decoder | heatmap, ROI·resize metadata | `(x_pixel,y_pixel,layer_z,score)` | model 좌표를 raw camera 좌표로 복원 |

실시간 제약은 stage별로 다르다. A head는 현재 B 또는 미래 Z를 사용할 수 없다. B·fusion은 해당 layer의 B가 확보된 뒤에만 실행한다. 각 stage의 입력은 3개 normalized LED intensity channel과 3개 aligned validity-mask channel로 구성한다. full-scale pixel은 intensity상 1로 clip될 수 있지만 mask 값 0으로 분리되어 denoising·heatmap loss에서 제외하거나 낮은 가중치를 받는다. 좌표 보정은 먼저 raw camera pixel에서 안정적으로 검증한 뒤 metadata의 calibration을 사용해 machine XYZ로 확장한다.

## 8. Causal Dataset sample 검증

Causal Dataset은 stage별 TIFF, causal manifest, `normalization_v1.yaml`을 결합해 memory 내에서만 sequence tensor를 생성한다. 원본 TIFF를 수정하거나 crop·mask·tensor 파일을 저장하지 않는다.

| 검증 sample | 기대 history | 확인된 history | Tensor shape | valid fraction | 판정 |
|---|---|---|---|---:|---|
| A train index 0 | z=1–4 | `1;2;3;4` | intensity `[4,3,256,256]`, mask `[4,3,256,256]`, input `[4,6,256,256]` | 0.2345 | 정상. 초기 layer의 높은 포화가 mask로 노출됨 |
| B validation index 0 | z=158–161 | `158;159;160;161` | intensity `[4,3,256,256]`, mask `[4,3,256,256]`, input `[4,6,256,256]` | 0.7175 | 정상. guard context만 사용 |
| A test index 0 | z=200–203 | `200;201;202;203` | intensity `[4,3,256,256]`, mask `[4,3,256,256]`, input `[4,6,256,256]` | 0.7740 | 정상. test가 validation endpoint를 history로 사용하지 않음 |

세 sample 모두 intensity 범위가 `[0,1]`, dtype이 `torch.float32`, stage ID가 A=0/B=1로 확인됐다. 특히 train 초반 valid fraction 0.2345는 오류가 아니라 early layer에서 포화가 강하다는 관측 결과이며, 별도 mask channel이 필요한 이유를 재확인한다.

## 9. Weak target 설정 원칙

등록판 `part01`~`part04`는 각 layer에 40-column CSV를 제공한다. 각 row는 XYPT command 위치에서 결합된 공정·LWI·XCT 측정점이며, column 38–40은 original·3×3×3·5×5×5 XCT voxel value다. 따라서 첫 target은 camera 이미지 전체의 확정 defect mask가 아니라 다음 형태의 **sparse continuous weak quality response**다.

```text
(part, layer_z, command_x_mm, command_y_mm, xct_5x5x5, supervision_support=1)
```

`xct_5x5x5`는 registration·voxel variability에 대한 완화 후보이지만, 아직 binary defect threshold가 아니다. CSV row가 없는 camera pixel은 정상(0)이 아니라 unknown이며, camera heatmap으로 확장하려면 machine XY→raw camera pixel calibration과 support-aware kernel 규칙이 필요하다. 이 separation은 dense negative label을 잘못 만들어 모델이 미관측 영역을 정상으로 학습하는 오류를 방지한다.

| target 단계 | 입력·출력 | 목적 | 아직 하지 않는 일 |
|---|---|---|---|
| Sparse target audit | registered CSV → coverage·distribution·XY support summary | finite XCT support와 train-only response 범위를 확인 | camera heatmap·binary label 생성 |
| Coordinate calibration | machine XY + layer-camera metadata → camera pixel transform | sparse target을 raw camera 위치에 배치할 수 있는지 검증 | calibration 밖 pixel에 target 부여 |
| Support-aware heatmap | calibrated sparse points → soft heatmap + supervision mask | location learning을 위한 공간적 약한 supervision 제공 | unsupported pixel을 negative로 간주 |
| Target config | target column·scaling·kernel·uncertainty policy | 학습 target을 재현 가능하게 고정 | XCT voxel 값을 확정 pore class로 주장 |

## 10. Registered XCT sparse-target audit 결과

등록 XCT audit은 part 4개와 layer 250개씩, 총 1,000 CSV를 검사했다. 4,748,352개 row가 모두 40-column schema를 만족했고, train history z=1–157에서 original·3×3×3·5×5×5 XCT value 각각 2,329,476개의 finite target을 확인했다. manifest의 validation/test target 값을 train distribution에 사용하지 않았다.

| part | 첫 finite XCT 5×5×5 layer | finite target 제공 layer | train history에서 XCT 미지원 layer | 정책 |
|---|---:|---|---|---|
| part01 | z=19 | z=19–250 | z=1–18 | z<19는 target loss 제외 |
| part02 | z=20 | z=20–250 | z=1–19 | z<20는 target loss 제외 |
| part03 | z=21 | z=21–250 | z=1–20 | z<21는 target loss 제외 |
| part04 | z=21 | z=21–250 | z=1–20 | z<21는 target loss 제외 |

초기 layer의 XCT 값 부재는 defect-free 판정이 아니라 **supervision unavailable** 상태다. 따라서 model input은 z=1부터 사용할 수 있지만, XCT-derived target loss는 part별 finite support가 있는 layer·machine-coordinate sample에서만 계산해야 한다. 네 part 모두 target이 가능한 공통 layer 범위는 z≥21이지만, part별 support mask를 유지하면 part01의 z=19–20과 part02의 z=20을 불필요하게 버리지 않는다.

전체 part의 train-only distribution에서 `xct_5x5x5`는 p01=0.40070, p50=0.54239, p99=0.58533, mean=0.53806, std=0.03338이었다. 5×5×5 filtered value는 registration·voxel neighborhood variability를 줄이기 위한 연속 weak response 후보로 유지한다. 이 수치는 아직 pore/defect binary cutoff나 anomaly direction을 확정하지 않는다.

## 11. Machine XY→raw camera pixel calibration 원칙

registered XCT target은 machine XY 좌표에 있고, Dataset input은 raw layer-camera pixel에 있다. 이 둘을 직접 연결하지 않으면 XCT value를 camera heatmap 위치에 올바르게 배치할 수 없다. raw B LED1은 포화·반사·좌측 obstruction이 강하고, raw camera의 화면 위·아래·좌·우가 machine X/Y 증가 방향과 같다는 보장도 아직 없다. 따라서 사용자가 machine `x_min/y_min`을 추정하도록 요구하지 않는다. 대신 B LED3 기준 frame에서 위에서 아래로 보이는 네 part의 screen TL/TR/BR/BL corner만 선택하고, calibration audit이 24개 part 배치와 8개 axis orientation 후보를 비교해 perspective를 포함한 2D transform 후보를 만든다.

| calibration 단계 | 산출물 | 필요한 이유 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|
| Screen-corner control-point selection | `screen_corner_controls_v2.json` | user가 확실히 판단할 수 있는 screen geometry만 기록하고 machine-axis 추정을 요구하지 않음 | top-to-bottom 4 part×screen TL/TR/BR/BL=16 points가 저장됨. 화면 표시가 축소돼도 click 좌표는 raw pixel로 환산 |
| Orientation hypothesis audit | 192개 part/orientation candidate의 residual·overlay QC | 잘못된 part 배치·mirror/rotation·단순 affine 가정을 탐지 | 낮은 residual 후보와 visual overlay가 동시에 일치 |
| Target projection eligibility | provisional machine→camera transform | sparse XCT sample을 camera pixel에 support-aware로 배치 | transform은 target config에 별도 고정 전까지 provisional |

orientation-hypothesis audit은 192개 후보를 비교했다. residual 기준 상위 두 후보는 모두 fit RMSE=5.212 px, leave-one-out RMSE=7.028 px로 3위(LOO RMSE=35.933 px)보다 크게 낮았다. 상위 1위는 `mirror_rotate_90`와 screen A→D=`part01, part02, part03, part04`이고, 2위는 그 전역 mirror 대칭인 `mirror_rotate_270`와 screen A→D=`part04, part03, part02, part01`이다. 두 후보는 모든 rectangle이 기하학적으로 유사한 구조라 residual만으로는 절대 machine part label과 mirror orientation을 구분할 수 없다.

따라서 현재 homography는 **geometrically plausible but orientation-ambiguous** 상태다. 낮은 residual은 part geometry가 raw camera image에 잘 맞는다는 근거이지만, target 정합을 자동 확정하지 않는다. registered LWI/raw intensity photometric tie-break도 실행했다. candidate 2의 median absolute Spearman correlation은 0.09560, candidate 1은 0.06469였으며, 각 후보에 432 stage·LED·filter·part·layer 비교가 포함됐다. candidate 2가 수치상 높지만 두 median 모두 0.10 미만이고 차이는 0.03091에 불과하므로, absolute orientation을 지지하는 충분히 강한 관측 신호로 해석하지 않는다.

낮은 상관은 7 px 수준의 residual, raw pixel과 registered nearest-LWI feature의 sampling footprint 차이, stage/LED illumination 및 saturation 차이에서 비롯될 수 있다. 따라서 각 candidate에 작은 global raw-pixel offset을 탐색하고, 5×5 local raw patch statistic과 registered mean5 LWI feature의 correlation surface를 비교했다. candidate 2는 interior offset `(dx,dy)=(0,-6)` px에서 median absolute Spearman 0.54282의 명확한 peak를 보였고, candidate 1의 최댓값 0.20692보다 약 2.62배 높았다. candidate 1의 peak는 탐색 경계 `dx=-12` px에 있어 안정적인 local optimum으로 해석할 수 없다.

따라서 `mirror_rotate_270`, screen A→D=`part04, part03, part02, part01`, raw pixel global correction `(0,-6)` px를 **provisional absolute orientation**으로 유지한다. 이 상태는 sparse XCT weak target의 support-aware specification을 설계할 수 있는 수준이지만, 향후 독립 calibration target으로 재검증 가능한 provisional transform이다. calibration 밖 pixel과 registered sparse support 밖 pixel은 target=0이 아니라 unknown으로 계속 유지한다.

## 12. 데이터 전처리에 적용한 수학적·기술적 기법

이 절은 실제로 적용·검증된 전처리와 현재 calibration/target 설정에 적용 중인 기법을 구분해 기록한다. 아직 결과가 없는 photometric tie-break와 dense weak heatmap은 완료 기법으로 표현하지 않는다.

| 단계 | 적용 기법·수식 | 입력→출력 | 필요한 이유와 방지하는 오류 |
|---|---|---|---|
| TIFF 축 해석 | ImageJ hyperstack 축 `TZYX=[LED, layer, Y, X]`; 1-based `(z, led)`를 0-based memmap index `(led-1,z-1,:,:)`로 변환 | 6 GB TIFF → 단일 2D frame | physical TIFF page 수가 1이므로 page-index 접근에서 발생하는 layer out-of-range 오류 방지 |
| Out-of-core 읽기 | `tifffile.memmap(mode='r')` | 원본 TIFF → 필요 frame만 virtual access | 6 GB 원본을 RAM에 전부 적재·재저장하지 않고 원본 불변성 유지 |
| Causal sequence | endpoint `z`에 대해 `H_z=[z-K+1,...,z]`, 현재 `K=4` | 2D frame → `[4,3,H,W]` history | future layer가 입력에 섞이는 시간 누수 방지 |
| Split·guard band | train endpoint 4–157, guard 158–160, validation 161–199, guard 200–202, test 203–250 | endpoint set → 독립 split | validation/test endpoint를 train history나 normalization에 사용하는 누수 방지 |
| ROI 후보 비교 | candidate ROI별 full-scale rate `r_sat = mean(x==65535)`와 valid ratio `1-r_sat` | raw A/B frame → ROI statistic | 외관상 중앙 crop만으로 sensor saturation 문제가 해결됐다고 오인하는 오류 방지 |
| Saturation validity mask | `m(x)=1[x<65535]` | raw `[K,3,H,W]` → mask `[K,3,H,W]` | sensor ceiling을 정상 texture·이상 signal·target=0으로 잘못 학습하는 오류 방지 |
| Robust normalization | stage·LED별 train-only `q01=P_1(x|m=1)`, `q99=P_99(x|m=1)`; `x_norm=clip((x-q01)/(q99-q01),0,1)` | uint16 intensity → `[0,1]` intensity | LED/stage illumination scale 차이와 outlier/saturation에 대한 global min-max bias 방지 |
| Resize·mask 분리 | intensity는 continuous resize, mask는 nearest-neighbor resize | ROI → model size 256×256 | invalid mask 경계가 interpolation으로 fractional intensity처럼 번지는 오류 방지 |
| Sparse XCT support | target support `s=1[finite(xct_5x5x5)]`; `s=0`은 unknown | registered CSV row → sparse weak supervision | XCT 값이 없는 초기 layer·camera pixel을 정상/negative label로 간주하는 오류 방지 |
| XCT smoothing 선택 | original·3×3×3·5×5×5 XCT voxel value를 별도 유지; 후보 response는 `xct_5x5x5` | sparse XCT voxel → continuous weak response 후보 | voxel neighborhood·registration uncertainty를 binary defect cutoff로 과도 해석하는 오류 방지 |
| Homography | `s[u,v,1]^T = H[X,Y,1]^T`, normalized DLT와 SVD로 `H` 추정 | machine XY → raw camera `(u,v)` | camera perspective를 단순 translation/affine으로 가정하는 오류 방지 |
| Calibration residual | fit `RMSE=sqrt(mean(||p_hat-p||^2))`, leave-one-out RMSE | 16 control points → geometric consistency score | control point overfit·오클루전 edge·잘못된 part 대응을 탐지 |
| Orientation hypothesis | 4! part assignment × 8 rotation/mirror = 192 hypothesis | screen corner controls → ranked homography candidates | raw camera axis를 machine X/Y와 임의로 동일시하는 오류 방지 |
| Photometric tie-break | projected raw A/B LED value와 registered LWI feature의 Pearson `r`·Spearman `rho` 비교; candidate score=`median(|rho|)` | geometry tie 후보 → feature-consistency score | 전역 mirror 대칭처럼 geometry residual만으로 구분 불가한 absolute orientation을 분리 |
| Local photometric refinement | `p'(X,Y)=p(X,Y)+(dx,dy)`; 5×5 valid patch mean과 registered mean5 feature의 `median(|rho|)` surface 탐색 | mirror 후보×offset grid → local peak | 1-pixel sample과 약 7 px residual에 민감한 global correlation의 한계 완화 |
| Support-masked regression | `L=Σ_i m_i·SmoothL1(p_i,y_i;β)/Σ_i m_i`, `β=0.1`, `m_i=1[weak_support_mask_i>0]` | candidate response·weak response·support → scalar loss | sparse XCT 미지원 pixel을 normal target으로 바꾸거나 loss gradient가 새는 오류 방지. `Σm=0`이면 differentiable loss=0 |

### 12.1 현재 사용되는 input tensor contract

현재 causal Dataset은 stage별 history에 대해 intensity와 mask를 별도 반환한다. intensity는 `[K,3,H,W]`, validity mask도 `[K,3,H,W]`, 결합 입력은 `[K,6,H,W]`이다. 각 LED는 해당 stage의 `q01/q99`를 사용하고 mask가 0인 full-scale pixel은 이후 denoising/heatmap loss에서 제외하거나 별도 가중을 받도록 설계한다.

### 12.2 Runtime weak-target 변환과 남은 의미 검증

`AMMTWeakTargetDataset`은 endpoint layer의 finite `xct_5x5x5` 행만 선택해 command XY(열 3–4)를 provisional homography로 raw camera pixel에 투영한다. working ROI를 model 256×256 좌표로 변환한 뒤 Gaussian kernel `G(d)=exp(-d^2/(2 sigma^2))`, `sigma=2`로 weighted-average rasterization을 수행한다. response는 train-only `p01=0.40070`, `p99=0.58533`으로 `clip((x-p01)/(p99-p01),0,1)` scaling하고, support는 kernel weight가 0보다 큰 pixel에서만 1이다. 이 모든 결과는 메모리 sample에만 존재하며 dense heatmap 파일로 저장하지 않는다.

target 방향은 아직 확정하지 않는다. 즉 `[0,1]` scaling은 수치 범위를 안정화할 뿐, 높은 값 또는 낮은 값을 anomaly라고 선언하지 않는다. 다음 loss는 `weak_support_mask==1` 위치에서만 regression을 계산해야 하며 `weak_target_available=false`인 early layer는 target loss를 0으로 만들어야 한다.

이 gate 중 하나라도 보류라면 다음 단계의 target을 생성하지 않는다. 특히 unknown 영역을 negative label로 바꾸거나, provisional calibration 결과를 확정 defect coordinate로 표현하지 않는다.

## 16. Projected sparse-XCT support audit 결과

Provisional calibration으로 finite `xct_5x5x5` sample 2,329,476개를 train history layer에 대해 raw camera plane으로 투영했다. 모든 finite sample이 2000×2000 camera FOV 안에 들어와 in-FOV fraction은 1.0000이었고, rounded raw pixel collision fraction은 0.02888이었다. layer 125 QC에서는 part04·part03·part02·part01 support가 raw camera의 네 part 영역에 위에서 아래로 분리돼 나타났다. 이는 geometry·local photometric refinement와 일관된 camera-space sparse support다.

이 결과로 support-aware weak target의 공간적 적합성은 통과했다. 단, `xct_5x5x5` gray-value가 높은 값/낮은 값 중 어느 방향이 물리적 anomaly를 뜻하는지는 아직 binary defect segmentation으로 검증되지 않았다. 따라서 다음 target 구현은 우선 **continuous XCT-derived quality response**와 support mask를 생성하며, 이를 ‘확정 결함 heatmap’ 또는 anomaly score로 부르지 않는다. response direction과 threshold는 XCT segmentation 또는 수동 검토로 별도 고정한다.

## 17. Weak target Dataset runtime 검증과 QC 아카이브

Projected sparse support와 sigma audit은 **공간 정책**이 구현 가능함을 보였지만, 실제 학습 Dataset에서 target가 정확한 endpoint layer에 연결되는지는 별도 검증이 필요하다. 특히 registered XCT가 아직 존재하지 않는 early layer를 response=0으로 채우면, 모델은 target 미관측을 정상 품질로 학습하게 된다. 반대로 support가 존재하는 layer에서 command XY·calibration·ROI resize·scaling 중 하나라도 불일치하면 response가 잘못된 위치에 나타난다.

## 18. Support-mask weighted continuous regression loss 검증

Weak target Dataset이 response와 support를 올바르게 반환하더라도, 학습 loss가 support 밖 pixel을 계산에 포함하면 sparse XCT의 미관측 영역이 모델 update에 영향을 준다. 이 위험을 막기 위해 `src/ammt_masked_regression_loss.py`는 global supported-pixel mean 형태의 Smooth L1 loss를 사용한다.

\[
L = \begin{cases}
\frac{\sum_i m_i\operatorname{SmoothL1}(p_i,y_i;\beta)}{\sum_i m_i}, & \sum_i m_i > 0\\
0, & \sum_i m_i=0
\end{cases}
\]

여기서 `p_i`는 model의 `[0,1]` candidate-response prediction, `y_i`는 `weak_response`, `m_i=1[weak_support_mask_i>0]`, `beta=0.1`이다. `Σm=0`일 때에도 scalar loss가 model graph에 연결된 0으로 반환되므로 training loop를 별도 분기하지 않아도 gradient가 정확히 0이 된다. Smooth L1은 response scaling의 작은 정합 오차에는 민감하게 반응하되, sparse weak response의 상대적으로 큰 국소 오차가 전체 loss를 과도하게 지배하는 것을 완화한다.

| 검증 활동 | 관측 결과 | 판정 및 모델 영향 |
|---|---|---|
| z=4 early unknown | available=false, supervised pixel=0, loss=0.0, supported/unsupported gradient absolute sum=0.0/0.0 | **통과.** XCT가 없는 early layer가 normal=0 target으로 변환되지 않으며 target-loss update를 일으키지 않는다. |
| z=128 supported endpoint | available=true, supervised pixel=3,439, zero-prediction baseline loss=0.60062975, supported gradient absolute sum=0.99932176 | **통과.** support가 존재하는 위치에서만 continuous regression signal이 전달된다. 이 loss 값은 학습 성능이 아니라 의도적으로 만든 zero prediction의 기준값이다. |
| Unknown prediction isolation | support 밖 prediction만 1000으로 변경한 loss=0.60062975, absolute loss difference=0.0, unsupported gradient absolute sum=0.0 | **통과.** sparse support 밖 camera pixel은 loss와 gradient에 완전히 차단된다. |

이 검증으로 A-only baseline이 사용할 target/loss contract는 준비됐다. baseline은 model의 raw candidate-map logits에 `sigmoid`를 적용해 `[0,1]` response prediction을 만든 뒤 이 loss에 전달한다. 그러나 loss 통과는 **high/low XCT response가 물리적 anomaly를 뜻한다는 검증이 아니다.** 그 방향이 확인되기 전에는 training/evaluation 화면과 포트폴리오에서 모두 `XCT-derived quality candidate`라는 중립적 표현을 유지한다.

## 19. A-only causal continuous quality-candidate baseline

첫 학습 baseline은 레이저 전 A(AfterSpreading) 영상만 사용한다. 이는 B(Burned)가 아직 존재하지 않는 real-time early-warning 시점에서도 동작 가능한 최소 시스템을 먼저 평가하기 위함이다. `src/train_a_only_baseline.py`와 `configs/a_only_baseline_v1.yaml`은 6채널 causal input, on-the-fly weak response, support-masked loss를 한 training/evaluation loop로 연결한다. 현재는 **코드 구현 완료·사용자 dry-run 및 첫 training 실행 대기** 상태다.

| 구성 | 입력·출력 | 적용 기법 | 해결하는 문제 |
|---|---|---|---|
| A-stage causal input | `[B,4,6,256,256]`: 최근 A layer 4개, 각 layer의 intensity 3ch+validity mask 3ch | manifest-driven causal history | B 또는 future layer를 조기 경보 input에 섞는 시간 누수 방지 |
| Frame encoder | 각 history frame의 6ch → spatial feature | small Conv2D + GroupNorm + SiLU | intensity와 saturation reliability를 함께 해석하는 기초 spatial feature 형성 |
| Temporal aggregation | ordered feature sequence → current endpoint feature | past-only padded Conv3D, temporal kernel=3 | layer 간 문맥을 사용하되 future layer를 참조하지 않음 |
| Candidate map | endpoint feature → `[B,1,256,256]` | 1×1 output logits + sigmoid | robust-scaled `[0,1]` weak response와 shape/range를 정합 |
| Training loss | prediction·weak response·support mask → scalar | support-masked Smooth L1, beta=0.1 | sparse XCT support 밖 unknown pixel의 loss/gradient 차단 |
| Validation checkpoint | epoch별 validation supported-pixel mean loss | best validation model 선택 | test target에 맞추어 model을 선택하는 leakage 방지 |
| Test candidate decoder | `[1,256,256]` map → top-5 local maxima | max-pooling NMS와 ROI scale 역변환 | dense heatmap을 저장하지 않고 `(x_pixel,y_pixel,layer_z,score)` 후보만 compact JSON으로 보존 |

A-only baseline은 raw candidate logits에 sigmoid를 적용한다. 그러나 이 sigmoid score는 `xct_5x5x5`의 robust-scaled continuous response를 추정하는 수치일 뿐, response direction이 unresolved인 상황에서 anomaly probability가 아니다. 후보 decoder는 model-space local maximum을 raw camera coordinate로 되돌리며, `layer_z`는 manifest endpoint에서 직접 가져온다.

실제 training run은 `outputs/a_only_baseline_v1/`에 checkpoint, epoch history, held-out test metrics, compact candidate JSON만 저장한다. raw TIFF/registered XCT CSV는 읽기 전용이며, on-the-fly target 외의 dense crop·mask·heatmap은 저장하지 않는다. output directory가 기존에 존재하면 overwrite 없이 중단하도록 해 이전 결과를 보존한다.

### 19.1 A-only baseline의 다음 검증 gate

| 순서 | 검증 | 통과 기준 | 통과 후 해석 |
|---:|---|---|---|
| 1 | dry-run | input `[1,4,6,256,256]`, prediction `[1,1,256,256]`, sigmoid range `[0,1]`, finite masked loss | code·Dataset·model·loss tensor contract 연결 확인 |
| 2 | training history | train/validation supported-pixel loss가 기록되고 valid checkpoint가 생성 | optimizer가 sparse support sample에서만 update됨을 확인 |
| 3 | held-out test | test masked loss와 candidate JSON이 생성 | future layer를 사용하지 않은 causal test 평가 확보 |
| 4 | physical direction review | XCT segmentation/manual review와 score spatial correspondence 점검 | score를 anomaly likelihood로 해석할 수 있는지 별도 판단 |

A-only baseline은 첫 번째 비교 기준이다. 이후 B-only와 A/B fusion은 동일한 weak target·masked loss·causal evaluation policy에서 A-only와 비교해야 한다. 그렇지 않으면 stage 차이, target policy 차이, training split 차이를 model architecture 성능 차이로 잘못 해석할 수 있다.

## 22. Checkpoint spatial diagnostic과 plateau-safe candidate decoder

Run 1에서 candidate score와 좌표가 모든 test endpoint에 반복된 문제는 loss 수렴 지표만으로는 발견할 수 없다. support-masked regression은 supported pixel 전체의 평균 오차를 줄이는 목적함수이므로, 공간적으로 거의 동일한 map도 target 평균 수준에서 어느 정도 loss를 줄일 수 있다. 따라서 localization project에서는 **loss와 spatial discriminativeness를 별도 gate로 검증**해야 한다.

이를 위해 `src/diagnose_a_only_spatial_predictions.py`를 추가했다. 이 read-only script는 저장된 checkpoint와 selected train/validation/test endpoint를 사용해 다음을 terminal JSON으로만 출력한다. checkpoint, raw TIFF, registered XCT CSV를 읽기 전용으로 접근하며 model update, dense image, output result file 생성은 수행하지 않는다.

| diagnostic | 계산 | 확인하는 문제 | 판정 활용 |
|---|---|---|---|
| prediction spatial range·population std | endpoint map의 `max-min`, `std` | model이 화면 전체에 constant/near-constant 값을 내는가 | range≤`1e-6`이면 plateau |
| supported target range·std | `weak_support_mask==1`의 `weak_response` 분포 | target 자체가 충분한 spatial variation을 가지는가 | prediction variation과 비교 |
| support 내 Pearson correlation | supported `prediction`과 `weak_response`의 centered dot product | response variation이 target variation을 따라가는가 | descriptive regression signal; direction/defect 의미 확정용 아님 |
| decoder status | spatial range gate 뒤 NMS 수행 여부 | flat-map tie가 물리 좌표로 변환되는가 | plateau면 candidate=0을 기대 |

동시에 `configs/a_only_baseline_v1.yaml`과 `src/train_a_only_baseline.py`를 보완했다. decoder는 `spatial_plateau_range_atol=1e-6`보다 작거나 같은 map range에서는 `withheld_spatial_plateau` status와 빈 candidate list를 반환한다. 이 tolerance는 anomaly threshold가 아니라 float-level flat map의 동점 top-k가 임의 좌표를 만드는 것을 막는 안전장치다. map variation이 확인된 endpoint만 기존 local-maximum NMS와 raw camera coordinate 역변환을 수행한다.

| decoder 결과 | 의미 | 후속 처리 |
|---|---|---|
| `emitted` | map에 plateau보다 큰 spatial variation과 finite local maximum이 존재 | candidate는 여전히 XCT-derived quality candidate로만 검토 |
| `withheld_spatial_plateau` | endpoint map이 사실상 평탄하여 위치 순위를 만들 근거가 없음 | candidate를 만들지 않고 model/target diagnostic 결과로 개선 실험을 설계 |
| `withheld_no_local_maximum` | 유한한 local maximum이 존재하지 않음 | numerical/data-flow 오류 여부를 추가 점검 |

이 정책은 허위 positive 좌표를 숨기기 위한 것이 아니라, **model이 위치를 구분하지 못할 때 그 사실을 명시적으로 출력**하기 위한 것이다. diagnostic 결과 후에는 model capacity, spatial regularization, supported target density/rasterization, training duration을 동시에 바꾸지 않고 하나씩 비교한다.


### 22.1 Decoder 통합 코드의 syntax QA

plateau-safe decoder 통합 후 diagnostic import 단계에서 `evaluate_test_candidates` 내부의 `history = sample["model_input_history"]...` 할당문이 손상된 SyntaxError가 발견됐다. 오류는 checkpoint, TIFF, XCT CSV 접근 이전의 Python import 단계에서 발생했으므로 raw data와 기존 run 1 output은 변경되지 않았다. 원래의 Dataset→model input 할당식을 복구하고 whitespace diff와 호출 지점을 정적으로 재점검했다.

이 사례는 candidate decoder처럼 결과 해석에 직접 영향을 주는 후속 기능을 추가할 때, 먼저 read-only diagnostic으로 import·tensor data flow를 검증해야 하는 이유를 보여 준다. 이후 user-run diagnostic이 정상 통과하기 전까지 decoder의 `withheld_spatial_plateau` 정책을 실제 output artifact에 적용했다고 주장하지 않는다.


### 22.2 Checkpoint spatial diagnostic 결과: global variation과 support-region plateau의 분리

`test_z_203`, `test_z_227`, `test_z_250`의 checkpoint diagnostic은 전역 prediction map이 완전히 constant가 아님을 보였다. 각 endpoint의 global range는 0.67868543, population standard deviation은 0.11746240, exact unique value count는 25였다. 따라서 단순 전역 `max-min≤1e-6` gate는 `flat_by_spatial_range_atol=false`가 되어 candidate를 막지 못했다.

그러나 sparse XCT support 내부에서의 prediction은 세 endpoint 모두 min=max=mean=0.67868608, standard deviation=0.0이었다. 반면 supported weak target은 endpoint별 standard deviation 0.13695, 0.14208, 0.15744와 range 0.81809, 0.81933, 0.85600을 가졌다. prediction-support Pearson correlation은 variance가 0인 경우 정의되지 않아 `null`이었다. 즉 model은 target이 실제로 달라지는 supported spatial region에서 map variation을 만들지 못하고, 고정된 spatial prior/plateau로 response 평균 수준만 근사했다.

| 관측 | 결론 | localization 영향 |
|---|---|---|
| Global prediction range>0 | map 전체에는 high/low 영역이 있다 | global range만으로 coordinate 신뢰성을 판단할 수 없다. |
| Support-region prediction std=0 | supervised 영역 내 상대 순위가 없다 | support 내 target 변화와 위치를 구분할 수 없다. |
| Support target std>0 | weak target 자체는 flat하지 않다 | 현재 병목은 target 부재가 아니라 model/optimization/feature의 spatially constant support prediction이다. |
| 동일 map 통계가 z=203/227/250에서 반복 | endpoint input 변화에 map이 반응하지 않는다 | run 1 coordinate를 physical candidate로 해석할 수 없다. |

따라서 기존 decoder의 global `max-min` gate는 안전 장치로 충분하지 않다. 다음 decoder diagnostic은 support-independent prediction map뿐 아니라 **상위-score plateau의 면적·동점 비율·endpoint 간 map similarity**를 검사해야 하며, 이 결과를 바탕으로 coordinate를 `withheld`할 기준을 정한다. 이 과정은 response direction을 정의하거나 defect label을 만드는 작업과 독립적이다.


### 22.3 Support-independent candidate withholding 확장

실시간 A-stage inference 시점에는 post-build XCT support mask를 알 수 없으므로, decoder가 support mask를 사용해 candidate를 보류하면 data leakage가 된다. 따라서 decoder의 후보 보류 기준은 model prediction map 자체와 과거 endpoint prediction map만 사용하도록 확장했다.

| 지표 | 계산 | 설정 기준 | withholding 결과 |
|---|---|---:|---|
| Full-map spatial range | endpoint map의 `max-min` | `≤1e-6` | `withheld_spatial_plateau` |
| Top-score tie fraction | max score와 절대차 `≤1e-6`인 pixel 수 / 전체 model pixel 수 | `>0.001` (0.1%) | `withheld_top_score_plateau` |
| Temporal map MAE | 현재 endpoint map과 바로 이전 endpoint map의 absolute difference 평균 | `≤1e-6` | temporal criterion의 첫 조건 |
| Temporal map max-absolute | 현재 endpoint map과 바로 이전 endpoint map의 largest absolute difference | `≤1e-6` | temporal criterion의 둘째 조건; 두 조건 동시 만족 시 `withheld_temporally_invariant_map` |

`top_score_tie_fraction_max=0.001`은 defect threshold나 score quality threshold가 아니다. 256×256 map에서 max-score tie가 65 pixel을 넘으면 하나의 위치를 대표할 수 없다는 decoder safety policy다. temporal criterion 역시 “layer마다 반드시 달라야 한다”는 물리 규칙이 아니라, numerically identical map을 반복할 때 top-k tensor ordering을 physical location으로 오인하지 않기 위한 guard다.

우선순위는 full-map flat, top-score plateau, temporal invariance, 그 뒤 finite local-maximum emission 순서다. support mask는 loss와 offline target diagnostic에는 계속 사용하지만 이 decoder decision에는 사용하지 않는다. `src/diagnose_a_only_spatial_predictions.py`는 user-selected endpoint 순서에서 이 지표와 withheld status를 terminal JSON으로 검증하며, persistent artifact를 만들지 않는다.


### 22.4 Extended decoder diagnostic 결과: input-invariant top-score plateau 확인

확장 diagnostic을 run 1 checkpoint의 test z=203, z=227, z=250에 실행했다. 세 endpoint 모두 top score 0.67868608을 공유하는 pixel 수가 63,504개였고, 전체 65,536 model pixel 중 96.8994%를 차지했다. 설정된 top-score tie fraction maximum 0.1%를 크게 초과하므로 세 endpoint는 모두 `withheld_top_score_plateau`로 candidate count 0을 반환했다. 이 결과는 decoder가 arbitrary top-k tensor order를 physical coordinate로 변환하지 않도록 안전하게 동작했음을 확인한다.

또한 z=203→z=227, z=227→z=250의 prediction map MAE와 max-absolute difference는 모두 0.0이었다. 즉 세 선택 endpoint의 input history가 다름에도 run 1 checkpoint는 정확히 같은 prediction map을 반복했다. top-score plateau gate가 먼저 적용되므로 terminal status는 temporal-invariant status가 아니라 `withheld_top_score_plateau`였지만, temporal invariance 지표 역시 input-invariant map을 독립적으로 뒷받침한다.

| 지표 | z=203 | z=227 | z=250 | 판정 |
|---|---:|---:|---:|---|
| Top-score tie pixel count | 63,504 | 63,504 | 63,504 | 0.1% 허용치를 초과 |
| Top-score tie fraction | 96.8994% | 96.8994% | 96.8994% | top-score plateau |
| Candidate decoder status | withheld | withheld | withheld | candidate count=0 |
| 이전 선택 endpoint와 MAE | 해당 없음 | 0.0 | 0.0 | temporal invariance |
| 이전 선택 endpoint와 max-abs | 해당 없음 | 0.0 | 0.0 | temporal invariance |

이 checkpoint의 문제는 “지원 영역에서만 평탄함”보다 더 강하다. output map의 약 97%가 같은 최고값이고, 서로 다른 test history에서도 map 전체가 정확히 불변이다. 이는 A-only input의 spatial/temporal variation이 current training regime에서 prediction으로 전달되지 않고, model이 response 평균과 고정 spatial boundary prior에 collapse했음을 보여 준다. 정확한 원인은 아직 확정하지 않는다. 가능한 원인은 training duration 부족, 작은 baseline capacity, sparse-target gradient structure, input feature utilization 중 하나 이상이다.

첫 개선 실험은 **training duration만 8에서 24 epoch로 늘리는 controlled run**으로 선택한다. epoch 8이 validation best였고 validation loss가 감소 중이었기 때문에, model architecture·target scaling·rasterization·optimizer를 바꾸지 않은 채 optimization time만 늘려 under-training 여부를 먼저 분리한다. 이 run에서도 map이 invariant하면 다음 단일 축은 model capacity가 된다. 반대로 variation이 생기면 held-out loss와 candidate withholding status를 함께 비교한다.

## 23. A-only controlled run 2: training duration 8→24 epoch

Run 1 checkpoint는 8 epoch에서 input-invariant top-score plateau를 보였다. 원인을 한번에 바꾸면 loss 변화가 training duration, model capacity, target construction 중 무엇 때문인지 분리할 수 없으므로, run 2는 epoch 수만 변경하는 controlled experiment로 설계했다. `configs/a_only_baseline_e24_v1.yaml`은 reference `configs/a_only_baseline_v1.yaml`과 비교해 `training.epochs: 24`, `storage.output_directory: outputs/a_only_baseline_e24_v1`만 다르다.

| 변경 변수 | run 1 | run 2 | 확인할 가설 |
|---|---:|---:|---|

E24 run에서 loss가 낮아지는 것만으로는 localization 통과가 아니다. run 1의 96.8994% top-score tie fraction, selected-endpoint map MAE/max-absolute=0, withheld status와 비교해야 한다. e24 map이 input variation에 반응하고 top-score tie가 충분히 감소해 decoder safety gate를 통과할 때만 coordinate candidate를 검토한다. 반대로 e24도 invariant plateau면 under-training 설명은 약해지고, 다음 controlled axis는 model capacity가 된다.


### 23.1 E24 training 종료 후 held-out evaluation recovery

E24 controlled run은 24 epoch training loop를 완료했고, validation best는 epoch 9의 0.06152481이었다. Run 1 best 0.06163192보다 absolute 0.00010711, relative 0.17% 감소다. 그러나 training 종료 뒤 test candidate 평가 loop에서 `sample=dataset[index]` 할당이 누락되어 NameError가 발생했다. checkpoint `outputs/a_only_baseline_e24_v1/best_validation_supported_loss.pt`는 이미 저장되어 있으며 raw source 및 checkpoint가 손상되지는 않았다.

이 오류가 발생한 위치는 training/validation이 끝난 뒤의 test candidate iteration이다. 따라서 24 epoch를 다시 실행하면 controlled comparison을 불필요하게 반복하고 자원을 낭비한다. loop에 sample 할당을 복구하고 `src/evaluate_a_only_checkpoint.py`를 추가했다. 이 recovery script는 saved checkpoint와 test Dataset을 read-only로 로드하고 optimizer, backward, random initialization, checkpoint overwrite 없이 held-out masked test metric 및 compact candidate JSON만 생성한다. 기존 output file이 있으면 overwrite를 거부한다.

| 항목 | 현재 상태 | 해석 |
|---|---|---|
| E24 train loop | 완료 | 24 epoch optimization은 유효 |
| Best validation checkpoint | epoch 9 저장됨 | recovery에서 그대로 재사용 |
| E24 held-out metric/candidate JSON | 오류로 미생성 | checkpoint-only recovery의 생성 대상 |
| Run 1 artifact | 변경 없음 | 공정 비교 reference 유지 |
| Raw TIFF/XCT CSV | 변경 없음 | read-only policy 유지 |

E24 test recovery가 끝난 뒤에만 run 1과 test loss·top-score tie·temporal invariance·candidate safety status를 비교한다. Epoch 9 이후 validation loss가 0.0615대에서 다시 상승했으므로, best checkpoint 기준 held-out 평가가 완료되어야 training-duration hypothesis를 수용하거나 기각할 수 있다.


### 23.2 Checkpoint-only evaluator loss-config compatibility recovery

첫 checkpoint-only evaluation 실행은 `configs/masked_regression_loss_v1.yaml`의 실제 schema가 `objective.beta`인데 evaluator가 존재하지 않는 `loss.smooth_l1_beta`를 참조해 KeyError로 종료됐다. 오류는 model/dataset/test loop에 도달하기 전 loss object 생성 시점에 발생했으므로 checkpoint, raw TIFF, registered XCT CSV, output directory는 변경되지 않았다. e24 output directory에는 `best_validation_supported_loss.pt`만 존재하고 `test_metrics.json` 및 `test_coordinate_candidates.json`은 여전히 없다.

Evaluator의 beta 참조를 `loss_config["objective"]["beta"]`로 복구했다. 이 값은 training script에서 사용한 SupportMaskedSmoothL1Loss의 beta=0.1과 동일하다. 따라서 재실행은 e24 checkpoint를 재학습하지 않고, run 1과 같은 loss 정의로 held-out test metric 및 plateau-safe candidate status만 산출한다.

| QA 항목 | 검증 결과 | 효과 |
|---|---|---|
| 실제 loss config schema | `objective.name`, `objective.beta=0.1` 확인 | key guess를 제거 |
| e24 output precondition | checkpoint 1개만 존재, test JSON 없음 | recovery write 대상이 명확 |
| overwrite policy | existing test JSON이면 evaluator가 중단 | 재실행이 prior result를 덮어쓰지 않음 |
| raw/checkpoint mutation | 오류 전후 모두 없음 | controlled-run artifact와 raw-data immutability 보존 |


## 24. E24 controlled-run 결과: training duration 가설 보류, 다음 축은 model capacity

Checkpoint-only held-out evaluation과 spatial diagnostic을 완료했다. E24 checkpoint는 epoch 9의 best validation state를 사용했고 test masked loss=0.07370871을 기록했다. Run 1 test loss=0.07344962보다 absolute 0.00025909, relative 0.35% 높다. Validation에서는 run 1보다 0.17% 낮았지만 held-out test에서는 개선되지 않았으므로, training epoch만 연장하면 spatial localization collapse가 해소된다는 가설은 지지되지 않는다.

| 지표 | Run 1: 8 epoch | E24 run: epoch 9 best checkpoint | 비교 결론 |
|---|---:|---:|---|
| Best validation masked loss | 0.06163192 | 0.06152481 | e24 −0.17%, 미세 개선 |
| Held-out test masked loss | 0.07344962 | 0.07370871 | e24 +0.35%, 미세 악화 |
| Global map unique values | 25 | 26 | 단순 output value 수 증가는 localization 근거가 아님 |

E24 validation loss는 epoch 9에서 최저였고 epoch 10–24 동안 약 0.0617–0.0623 범위로 상승 또는 정체했다. 이는 training duration을 24로 늘렸더라도 최적 checkpoint가 초반에 선택됐음을 뜻한다. 따라서 다음 controlled axis로 **model capacity**를 선택한다. 다음 실험은 run 1과 동일하게 epoch=8을 유지하고 base channel 수만 8→32로 올린다. 입력, target, loss, optimizer, seed, split, decoder policy를 변경하지 않아 더 큰 feature capacity가 input-dependent spatial variation을 복원하는지 분리할 수 있다.

모델 capacity experiment의 통과 조건은 loss 단독 개선이 아니다. (1) held-out masked loss, (2) top-score tie fraction의 급격한 감소, (3) 서로 다른 endpoint map의 nonzero difference, (4) candidate safety gate 통과 여부를 함께 확인해야 한다. 여전히 plateau면 다음 원인은 target representation 또는 feature use로 남으며, response direction unresolved 상태에서는 score를 defect probability로 부르지 않는다.


## 25. C32 controlled model-capacity experiment

Run 1과 E24 run은 training duration만 바꿨지만 top-score tie fraction=96.8994%와 endpoint map invariance=0을 모두 유지했다. 다음 가설은 8-channel base model이 A-stage intensity·validity-mask·four-layer temporal pattern을 분리할 feature capacity가 충분하지 않아 fixed spatial prior로 collapse했다는 것이다.

C32 config `configs/a_only_baseline_c32_v1.yaml`은 run 1 `configs/a_only_baseline_v1.yaml`에 대해 effective model hyperparameter인 `model.base_channels`만 8→32로 변경한다. Training epoch=8로 되돌리고 sequence K=4, six input channels, ROI, normalization, command-XY calibration, weak response, sigma=2 rasterization, support-masked Smooth L1, AdamW, learning rate, seed, split, candidate decoder policy를 고정한다. 별도 output `outputs/a_only_baseline_c32_v1/`을 사용하므로 prior run artifact를 덮어쓰지 않는다.

| 실험 축 | Run 1 | C32 | 고정 이유 |
|---|---:|---:|---|
| Base feature channels | 8 | 32 | 유일한 capacity change |
| Epoch | 8 | 8 | duration confound 제거 |
| Input | A `[K=4,6,256,256]` | 동일 | data information 고정 |
| Target/loss | sparse continuous XCT + support-masked Smooth L1 | 동일 | supervision semantics 고정 |
| Optimizer/seed/split | AdamW, 0.0003, 20260827, causal split | 동일 | stochastic/selection confound 최소화 |
| Candidate decoder | support-independent safety gates | 동일 | localization claim 기준 고정 |

C32의 통과는 loss 하나로 결정하지 않는다. Held-out masked loss가 줄고, top-score tie fraction이 run 1/E24의 96.8994%보다 크게 낮아지며, 서로 다른 endpoint map MAE/max-absolute가 0을 벗어나고, decoder가 safety gate를 통과한 unique local maximum만 반환해야 한다. Candidate가 나온 뒤에도 response direction이 unresolved이므로 candidate는 continuous quality response 위치일 뿐 confirmed defect가 아니다.


## 26. C32 capacity experiment 결과: capacity 가설 보류, 다음 축은 target support density

C32 run은 `base_channels=32`로 feature capacity만 4배 늘리고 run 1과 동일한 8 epoch·input·target·loss·optimizer·seed·split·decoder policy를 사용했다. Best validation checkpoint는 epoch 1에서 선택됐고 held-out test masked loss=0.07363038이었다. Run 1 test loss=0.07344962보다 absolute 0.00018076, relative 0.24% 높아 held-out regression 성능 개선을 보이지 않았다.

C32는 global map의 spatial range=0.11245, std=0.00806으로 run 1/E24와 다른 고정 spatial pattern을 만들고 top-score tie를 96.8994%에서 0.3845%로 줄였다. 하지만 support 내부 prediction은 여전히 단일값 0.68430936이고, z=203/227/250 map의 MAE/max-absolute는 0/0이다. 따라서 capacity 증대는 static output geometry를 바꾸었을 뿐 A input에 따른 위치별 quality response를 복원하지 못했다. Capacity 가설은 localization 원인으로 채택하지 않는다.

다음 단일 가설은 **support-density target-rasterization**이다. 현 sigma=2의 layer-level support fraction은 대표 layer 125에서 약 3.62%였고 actual test support는 약 3,569–3,636 / 65,536 pixel이다. Sparse masked regression은 support 내부만 gradient가 생기므로 model이 각 sample의 fine spatial variation보다 global mean/fixed prior로 수렴할 수 있다. 다음 단계에서는 원본 CSV/response, calibration, normalization, model, loss, optimizer, epoch를 변경하지 않고 sigma만 2→3으로 바꾼 on-the-fly weak target rasterization audit을 먼저 수행한다. sigma=3 support increase가 과도한 spatial blurring 없이 gradient coverage를 높이는지 확인한 뒤에만 sigma=3 training config을 준비한다.

이 단계에서도 response direction은 unresolved다. Rasterization support expansion은 binary defect label을 만들거나 target direction을 반전하지 않으며, support 밖 unknown policy를 유지한다.

### 26.2 Sigma=2 vs 3 support-density audit 결과: sigma=3 training 보류

사용자 실행은 `processed/weak_target_support_density_v1/`에 compact CSV 2개와 summary JSON만 생성했으며, TIFF/raw CSV/dense target/checkpoint/model을 변경하지 않았다. z=4는 sigma=2/3 모두 support=0으로 남아 early XCT absence가 정상(0)으로 바뀌지 않았음을 확인했다. 나머지 8개 available endpoint는 train, validation, test에 걸쳐 비교됐다.

## 27. C32 stagewise input-sensitivity diagnostic 구현

`src/diagnose_a_only_input_sensitivity.py`를 추가했다. 이 diagnostic은 C32 best-validation checkpoint와 `AMMTCausalStageDataset`의 A-stage history만 읽는다. `AMMTWeakTargetDataset`을 사용하지 않으므로 registered XCT CSV, weak response, support mask, masked loss, candidate decoder를 참조하지 않는다. 목적은 target 품질을 다시 평가하는 것이 아니라 A input variation이 network path를 통과하는지 확인하는 것이다.

| 측정 stage | 계산 | 확인 질문 |
|---|---|---|
| `input_history` | 3 intensity + 3 saturation-mask의 `[K,6,H,W]` pairwise MAE/max-abs | 선택한 A history가 실제로 다른가 |
| `encoded_final_history_frame` | frame encoder의 마지막 history frame feature | endpoint frame의 image feature가 구분되는가 |
| `encoded_history` | 4-step 전체 frame-encoder feature | 과거 layer를 포함한 feature sequence가 구분되는가 |
| `temporal_final` | past-only padded Conv3D+GroupNorm+SiLU의 final feature | causal aggregation이 variation을 유지하는가 |
| `logits` | decoder의 pre-sigmoid response map | decoder가 temporal feature 차이를 유지하는가 |
| `score` | sigmoid final map | output activation 이후에도 차이가 남는가 |

세 selected sample의 모든 pair에 대해 stage별 MAE, max-absolute, RMSE, relative L2를 출력한다. `max_abs > 1e-6`이면 numerical distinction으로 표시하고, earliest stage가 모든 pair에서 distinction을 잃는 지점을 summary conclusion으로 반환한다. 이는 localization success criterion이 아니라 collapse origin 후보를 좁히는 diagnostic rule이다.

Script 내부에는 stagewise reconstruction score와 model `forward()` score의 max-absolute difference가 1e-6 이하인지 검증하는 self-consistency check도 있다. 불일치하면 output을 해석하지 않고 오류로 중단한다. Script는 terminal JSON만 출력하며 raw TIFF는 `tifffile.memmap(..., mode="r")`로 읽고, XCT CSV·target·checkpoint·optimizer·output file은 수정하거나 생성하지 않는다. Python 구문과 whitespace static check를 통과했다.

### 27.1 C32 stagewise input-sensitivity 결과: temporal aggregation collapse 확인

C32 epoch-1 checkpoint에 대해 test z=203/227/250 (dataset index 0/24/47)을 비교했다. 각 sample의 stagewise reconstruction과 ordinary `model.forward()` score의 max-absolute difference는 0으로, exposed internal path가 deployed forward path를 정확히 재현했다.

| Stage | z203↔227 pairwise MAE / max-abs | z203↔250 pairwise MAE / max-abs | z227↔250 pairwise MAE / max-abs | 판정 |
|---|---:|---:|---:|---|
| `input_history` | 0.051439 / 1.000000 | 0.053852 / 1.000000 | 0.050687 / 1.000000 | A input history는 명확히 다름 |
| `encoded_final_history_frame` | 0.065464 / 2.295962 | 0.068151 / 2.033926 | 0.063598 / 1.931690 | frame encoder가 endpoint image variation을 보존 |

따라서 earliest stage not distinct는 `temporal_final`이며, C32의 current static prediction map은 frame encoder 또는 sigmoid가 아니라 `Conv3D → GroupNorm → SiLU` temporal aggregation path에서 input variation을 잃는 현상으로 직접 확인됐다. `temporal_final`의 per-sample std=0.00179819와 L2 norm=2.60451은 encoded feature std≈0.593·L2≈913보다 매우 작지만, 이 수치 크기만으로 기계적 원인을 단정하지 않는다. 이 checkpoint와 선택 input에서 temporal aggregation/normalization path가 all-zero pairwise difference를 만든다는 사실만 확정한다.

다음 단일 controlled improvement는 model의 endpoint frame feature가 decoder까지 guaranteed causal path로 전달되도록 `temporal_final = encoded_endpoint + temporal_update` 형태의 optional residual bypass를 도입하는 것이다. 이 skip은 current layer A feature만 사용하므로 causality를 깨지 않으며, temporal context는 residual update로 계속 유지한다. 하지만 training config, model code, loss 또는 target 변경은 별도 승인 전까지 수행하지 않는다.


## 28. Endpoint-feature temporal residual controlled experiment 구현

C32 input-sensitivity 결과에 따라 `AOnlyCausalCandidateNet`에 `use_endpoint_feature_residual: bool = False` 옵션을 추가했다. Default `False`는 C8/E24/C32 config에 flag가 없을 때 기존 forward equation과 parameter/state-dict 구조를 그대로 유지한다. 즉 기존 checkpoint는 새 model class에서 `model_config.get(..., False)`로 계속 read-only 복원할 수 있다.

Residual config에서만 equation은 다음과 같다.

```text
encoded_endpoint = frame_encoder(current endpoint A frame)
temporal_update  = SiLU(GroupNorm(past-only Conv3D(encoded causal K=4 history)))
temporal_final   = encoded_endpoint + temporal_update
score             = sigmoid(decoder(temporal_final))
```

| 변경 파일 | 변경 내용 | C8/E24/C32 영향 |
|---|---|---|
| `src/train_a_only_baseline.py` | default-off residual option, residual forward branch, config `.get(..., False)` | flag 없으면 기존 architecture/equation 유지 |
| `src/diagnose_a_only_spatial_predictions.py` | config의 optional flag를 model 생성에 전달 | 기존 config는 false, residual checkpoint도 올바른 forward 복원 |
| `src/evaluate_a_only_checkpoint.py` | config의 optional flag를 model 생성에 전달 | 기존 checkpoint-only evaluator 동작 보존 |
| `src/diagnose_a_only_input_sensitivity.py` | residual branch를 stagewise reconstruction에 동일 반영 | residual checkpoint diagnostic self-consistency 유지 |
| `configs/a_only_baseline_c32_temporal_residual_v1.yaml` | C32 대비 residual=true와 new output directory만 가진 controlled config | C32 reference와 비교 가능 |

Residual은 current endpoint A frame feature를 decoder까지 직접 전달하고 temporal update는 과거 포함 K=4 history에서 얻는다. 따라서 future Z·B-stage·XCT target를 추가하지 않아 causality, A-only early-warning policy, response direction, sparse support/unknown policy를 변경하지 않는다. Model capacity=32, temporal kernel=3, target sigma=2, loss, optimizer, seed, batch size, epoch=8, decoder gate를 모두 C32와 고정한다.

`diff -u`로 C32/residual config 차이가 model residual flag, comparison prose, output path뿐인지 검토했고, training/spatial diagnostic/checkpoint evaluator/input-sensitivity diagnostic의 모든 `AOnlyCausalCandidateNet` 생성 경로가 same option을 전달하는지 static grep으로 확인했다. 네 Python source의 `py_compile`과 repository `git diff --check`도 통과했다. 이 정적 검증은 model training, TIFF/XCT read, target/output generation을 수행하지 않았다. 다음 user dry run이 residual config의 input/target/loss/model shape 및 finite masked loss를 runtime에서 처음 확인한다.

## 30. Calibration-aware compact candidate coordinate audit 구현

Residual run의 `test_coordinate_candidates.json`은 raw camera pixel center (`x_pixel`, `y_pixel`)와 originating 256×256 model-grid index (`x_model_pixel`, `y_model_pixel`)를 모두 담는다. 새 `src/audit_a_only_candidate_coordinates.py`는 이 compact JSON, residual model config, normalization ROI, calibration config와 16-point control JSON만 읽어 candidate coordinate convention을 검증한다. TIFF, registered XCT CSV, support mask, target, checkpoint를 읽지 않으며 inference/training도 하지 않는다.

### 30.1 변환 contract

Decoder와 같은 center convention을 이용한다.

```text
raw_camera = roi_start + (model_grid_index + 0.5) × raw_pixels_per_model_pixel
machine_xy = inverse(H_machine_to_raw) × (raw_camera - global_offset)
reprojected_raw = H_machine_to_raw × machine_xy + global_offset
model_grid_round_trip = (raw_camera - roi_start) / raw_pixels_per_model_pixel - 0.5
```

여기서 H는 current calibration rank 2 (`mirror_rotate_270`, raw offset `[0,-6]`) control points로 재계산한 machine XY→raw camera homography다. audit은 H의 inverse가 풀리는지, raw→machine→raw 및 model→raw→model arithmetic residual이 tolerance `1e-6` 이내인지 검사한다. 이 round trip은 **configured provisional transform의 internal arithmetic**만 검증하며 5.212px fit RMSE / 7.028px LOO RMSE를 가진 calibration의 absolute metrology accuracy를 새로 증명하지 않는다.

### 41.3 First runtime attempt: graph fragmentation hold
